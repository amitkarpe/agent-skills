# JSON Spec Contract

Use this reference when producing an HTML report through the deterministic renderer.

This skill follows the json-render mental model:

1. **Catalog**: the approved components the AI may use.
2. **Spec**: the small JSON document generated by the AI.
3. **Registry/renderer**: Python functions that turn approved component types into offline HTML.
4. **Validation**: `validate_spec.py` rejects unknown components, missing props, broken children, external URLs, and credential-like text before rendering.

`scripts/validate_spec.py` plus `references/component-catalog.json` is the
authoritative safety gate. `schemas/report.schema.json` is only an editor/shape
hint and must not be treated as the security validator.

## Required spec shape

Use a flat tree with `root` and `elements`, similar to json-render's React schema:

```json
{
  "schema_version": "1.0",
  "skill": "visual-explainer",
  "title": "Report title",
  "root": "page",
  "elements": {
    "page": {
      "type": "Page",
      "props": {},
      "children": ["hero", "summary"]
    },
    "hero": {
      "type": "Hero",
      "props": {"title": "Report title", "subtitle": "One-line purpose"},
      "children": []
    },
    "summary": {
      "type": "TLDR",
      "props": {"items": ["Point one", "Point two"]},
      "children": []
    }
  }
}
```

## Determinism rules

- Use only component types listed in `references/component-catalog.json`.
- The root element must exist and must have type `Page`.
- Do not write raw HTML, CSS, JavaScript, SVG, or external URLs in the spec.
- Put content in `props`; let the renderer own layout, styling, SVG, navigation, and print CSS.
- Keep IDs short and stable, for example `hero`, `flow`, `risks`, `next`.
- Keep children deterministic: the order in `children` is the rendered order.
- Prefer semantic components over low-level layout components.
- Do not use `visible` or conditional rendering fields; keep the first version deterministic and explicit.

## Required workflow

```text
1. Write report.spec.json
2. Run scripts/validate_spec.py report.spec.json
3. Run scripts/render_html_from_spec.py report.spec.json output.html
4. Run scripts/validate_html.py output.html
5. Publish with scripts/publish_html.py if the user wants LAN output
```

## Fallback rule

Direct handwritten HTML is allowed only when the requested page cannot be represented by the catalog. If using fallback HTML, still follow `DESIGN.md`, run `validate_html.py`, and keep the page self-contained/offline.
